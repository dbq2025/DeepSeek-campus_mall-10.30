### 1.3 前端页面覆盖

- 前台 11 页：首页、商品列表、商品详情、购物车、确认订单、我的订单、订单详情、我的收藏、个人中心、登录、注册。

### 1.4 明确不包含（范围外）

| 不做项 | 原因 | 边界处理 |
|---|---|---|
| 真实支付、退款、退款单 | 两份课程要求均未要求；退款涉及资金反向链路 | 只做 `pay` 模拟状态迁移；无退款态 |

| 真 SKU、多规格库存、多仓 | 阶段 1 已定方案 B | `spec_json` 仅展示 + `spec_text` 快照；库存仍在 `product` |
| 搜索中间件、推荐算法 | 课程无要求 | 关键词 `LIKE` + 排序白名单 |
| 用户资料编辑、改密、找回密码、地址簿 | 前端只有只读个人中心 | 收货信息仅在下单时快照 |
| 管理员用户管理、角色管理 | 无页面、无契约 | 只保留种子管理员 |
| 商品导入/导出、订单导出 | 无页面、无契约 | 不做 |
| 多模块 Maven、MQ、分布式锁、XXL-Job、Docker 部署、Nginx 生产化、Swagger、代码生成器、MapStruct、Druid、H2 | 阶段 2 反清单 | 不引入；新增依赖须单独批准 |
| 前端 UI/交互改版 | 阶段 4.5 已交付 | 本阶段最多改 2 个联调文件，见 D3/D10 |

#### B1 · 数据层与种子数据（P1）

- 7 个实体：`User`、`Category`、`Product`、`Cart`、`Orders`、`OrderItem`、`Favorite`；字段与 `schema.sql` 一一对应，`@TableId(type = ASSIGN_ID)`；`Product`/`Orders` 的 `deleted` 加 `@TableLogic`。
- 类型约定：只有 ID 用 `Long`（全局转字符串）；库存、数量、销量、计数、状态一律 `int/Integer`，避免被 Long 序列化器转成字符串；XML 中 `user` 表名加反引号。
- 7 个 Mapper：单表继承 `BaseMapper`；多表/统计用 XML：
  - `ProductMapper.xml`：前台/后台分页、详情、分类联表；
  - `OrderMapper.xml`：前台/后台分页、详情、`userName` 联表；
  - `StatMapper.xml`：概览、趋势、状态分布、热销；
  - 单表条件更新（扣库存、状态迁移）可用注解或 XML，但必须条件更新。
- 种子数据 `db/data.sql`：
  - 3 个账号：`admin/123456`（ADMIN）、`student/123456`（USER）、`test/123456`（USER），BCrypt 存储；
  - 4 个类型、14 个商品（含 1 个下架、2 个零库存、低库存样本）、2 条购物车、5 条订单覆盖状态 0–4、2 条收藏；
  - 时间用 `DATE_SUB(NOW(), INTERVAL ...)` 相对生成；**待付款种子订单必须控制在 30 分钟内**，否则启动后会被超时任务立即取消；答辩/演示前先执行 `reset-demo-data.sql`，保证待付款订单新鲜；
  - 固定主键，`ON DUPLICATE KEY UPDATE` 保证可重复执行；脚本头注明「仅本地演示库」。
- `db/reset-demo-data.sql`：按固定 ID 清理并重灌，供冒烟/答辩复位；不接入 `spring.sql.init` 自动执行。
- 出口：`data.sql` 连续执行两次行数不变；7 表映射查询通过；待付款订单在启动 1 分钟后仍为状态 0。

#### B2 · 认证与安全闭环（P1）

- `AuthController` + `AdminAuthController`；`AuthService`；`UserMapper`。
- 注册：用户名 4–20、密码 6–20、昵称必填 ≤20、邮箱可空；空邮箱存 `NULL`；重复用户名/邮箱 3004；BCrypt；注册即登录。
- 登录：用户名/密码/状态；管理员登录校验 `role=ADMIN`；失败 2004；禁用 2003。
- `GET /auth/me`：按 `SecurityUtil.currentUserId()` 查库，返回最新资料；用户不存在/禁用 2001/2003。
- `POST /auth/logout`：无状态，仅记录日志，返回 `null`。
- 安全骨架修正：
  - `SecurityConfig` 只放行 `/auth/login`、`/auth/register`、`/auth/admin/login`、`/auth/logout`；`/auth/me` 必须认证；
  - `JwtAuthFilter` 解析失败设置 `jwt.error`；`AuthenticationEntryPoint` 根据该属性返回 **2002**，无令牌返回 **2001**；
  - 放行 `OPTIONS /**` 与 `/error`；
  - `GlobalExceptionHandler` 补 `MethodArgumentTypeMismatchException`、`MissingServletRequestParameterException`、`ConstraintViolationException`、`MaxUploadSizeExceededException`、`NoResourceFoundException`。
- 出口：认证矩阵 12 条通过（无 token、坏 token、过期 token、用户/管理员、禁用、重复注册、空邮箱、错误密码、退出后再访问）。

#### B3 · 前台商品与类型（P1）

- `ProductService`、`CategoryService`；`controller/front/ProductController`。
- 列表：`keyword` 匹配 `name/subtitle`、`categoryId`、`sort` 白名单（`default/price_asc/price_desc/sales_desc/new`）、`page/size`；只返回 `status=1 AND deleted=0`；联表带 `categoryName`；排序下推 SQL；`default` 固定为 `create_time DESC, id DESC`，保证分页稳定。
- 详情：联表 + `favorited`（可选登录）；`status!=1` 3005；`deleted=1` 3003。
- 类型：按 `sort` 升序；可选加 `CacheService` 缓存（D8）；缓存读写异常必须降级查库，不能因 Redis 不可用导致接口失败。
- 分页字段修正：`PageResult` 的 `total/current/size/pages` 改为 number（推荐 `int`；若坚持 `long`，加字段级数字序列化器），禁止输出字符串。
- 出口：游客列表/详情/类型；关键词/分类/4 种排序/分页；下架 3005；删除 3003；`total` 为 number。

#### B4 · 购物车（P1）

- `CartService`、`controller/front/CartController`；规格校验/归一化工具（与订单共用）。
- 列表：按当前用户；联表商品；商品删除时占位（名称「商品已删除」、`productStatus=0`、`stock=0`）；`totalQuantity/totalAmount`。
- 加购：校验商品存在/上架/数量≥1/规格合法；同 `(user_id, product_id, spec_text)` 用 `INSERT ... ON DUPLICATE KEY UPDATE quantity=quantity+?` 原子合并；返回 `CartItem`。
- 改量：校验归属、数量≥1、库存；超库存 3001。
- 删除/清空：仅当前用户；不存在 3003。
- 出口：同规格合并、不同规格两行、改量 3001、删他人行 3003、清空后角标 0。

#### B5a · 下单与订单查询（P1，关键批次）

- `OrderService`、`controller/front/OrderController`；`OrderNoUtil`；订单/明细实体与 Mapper。
- 创建订单（`@Transactional(rollbackFor=Exception.class)`）：
  1. 校验收货人/手机号/地址/备注；
  2. `fromCart=true`：按 `user_id + cartIds` 查询，缺一行即 3003；`fromCart=false`：校验 items 非空、数量、规格；
  3. 全量校验商品存在/上架/规格/库存，**先校验后扣减**；
  4. 按 `product_id` 升序聚合数量，执行 `UPDATE product SET stock=stock-? WHERE id=? AND stock>=? AND status=1 AND deleted=0`；影响行数 0 → 3001，整单回滚；
  5. 按 D1 处理销量：选 B（推荐）时下单阶段**不**加销量，支付成功后再加；选 A 时在此处加销量；
  6. 写 `orders` + `order_item` 快照（名称/图片/单价/规格/行小计）；
  7. 清理已下单购物车行；返回 `orderId/orderNo/payAmount`。
- 订单号：`yyyyMMddHHmmss` + 6 位序列/随机；唯一索引兜底；冲突提示重试。
- 列表：按当前用户、状态可选、时间倒序、分页；批量查明细（避免 N+1）；`statusText` + `actions[]`。
- 详情：本人校验（不存在 3003，非本人 2003）；返回地址/时间/单号/取消原因。
- 出口：购物车下单/立即购买；扣库存；取消回补；快照价不随商品改价；订单列表最多 3 条 SQL（订单 + 明细 + 用户/统计）。

#### B5b · 状态动作与超时（P1，关键批次）

- 状态机集中在 `OrderStatus` 枚举：5 个状态、5 条合法迁移、禁止迁移表；非法统一 3002。
- 所有迁移用条件更新 `WHERE id=? AND status=?`；影响行数 0 时按顺序回读：订单不存在 → 3003；非本人（用户侧动作）→ 2003；已是目标态 → 幂等成功；否则 3002。
- `pay`：`0→1`，写 `pay_time`，`pay_amount=total_amount`；已支付幂等。按 D1 选 B 时，成功后按明细累加 `product.sales`（同一事务，失败回滚）；选 A 时下单已加，不重复加。
- `cancel`：`0→4`，写 `cancel_time/cancel_reason`；成功后回补库存；重复取消幂等且不二次回补。按 D1 选 A 时同步回退销量（`sales = GREATEST(sales - ?, 0)`）；选 B 不回退。
- `confirm`：`2→3`，写 `finish_time`；重复确认幂等。
- `ship`（后台 B8 实现，但状态机在 B5b 定稿）：`1→2`，写 `ship_time/tracking_no`；按 D4 处理重复发货。
- 超时任务 `OrderTimeoutTask`：
  - `@Scheduled(fixedDelay=300000, initialDelay=60000)`；
  - 配置 `mall.order.timeout-minutes=30`、`timeout-scan-limit=100`、`timeout-enabled=true`；
  - 只查 `status=0 AND create_time < now-30min`，批量 100，逐单调用 `orderService.timeoutCancel(id)`（跨 Bean 调用，事务生效）；
  - 原因「超时未付款」；回补库存（D1 选 A 时同步回退销量）；单条失败记录日志不阻断其他单。
- 出口：5 条合法 + 5 条非法迁移；支付/取消/确认幂等；超时旧单取消且库存只回补一次；新单不被误取消。

#### B6 · 收藏（P2）

- `FavoriteService`、`controller/front/FavoriteController`。
- 列表：按用户、时间倒序、分页；联表商品；逻辑删除商品过滤（D6）；返回 `favoriteId/favoriteTime` + 商品字段。
- 添加：商品存在/上架；唯一键冲突 3004。
- 取消：按 `user_id + productId` 删除；按 D5 决定「未收藏」返回 3003 或幂等成功。
- 状态：`{favorited:boolean}`；未登录 401。
- 出口：重复收藏 3004、取消后详情态 false、下架商品按 D6 处理。

#### B7 · 后台类型、商品与上传（P2）

- `CategoryService` + 后台 `CategoryController`：下拉、分页（`productCount` 子查询，只统计 `deleted=0`）、新增/编辑（名称唯一）、删除（有未删除商品引用 3002）。
- `ProductService` + 后台 `ProductController`：分页（`keyword/categoryId/status`）、详情（含下架）、新增/编辑、单个/批量上下架、逻辑删除。
- `ProductForm` 校验：分类存在、名称/副标题长度、价格≥0 且 ≤2 位小数、库存≥0、状态 0/1、`spec_json` 结构合法（名称/取值非空且不重复，总长≤500，生成 `spec_text`≤100）。
- `FileService` + `FileController`：`multipart/form-data` 字段 `file`；白名单 jpg/jpeg/png/webp；≤2MB；UUID 文件名；按 `yyyy/MM` 分目录；返回 `/files/yyyy/MM/uuid.ext`；拒绝路径穿越。同步把 `spring.servlet.multipart.max-file-size` 调为 `2MB`、`max-request-size` 调为 `3MB`，业务层再校验一次。
- `WebConfig`：上传目录静态映射 + `classpath:/static/files/` 兜底；把前端 `public/files/p1–p8.svg` 复制到后端 `src/main/resources/static/files/`，保证种子商品图可访问。
- 类别写操作清理分类缓存（若启用 D8）。
- 出口：类型 CRUD + 删除保护；商品 CRUD + 批量上下架 + 逻辑删除；4 类上传用例；种子图片 200。

#### B8 · 后台订单与统计（P2）

- 后台 `OrderController`：分页（`orderNo/status`，联表 `userName`）、详情、发货、代确认收货；动作由 `actions[]` 驱动。
- `StatService` + `StatMapper.xml`：
  - 概览：今日订单（不含已取消）、今日成交额（按 `pay_time`）、待发货、商品总数（未删除）、注册用户数（按 D7）；
  - 趋势：`days` 1–30，Java 生成日期序列，SQL 按日聚合，缺失日补 `"0.00"`；
  - 状态分布：固定 5 行，缺失补 0；
  - 热销：按 `product.sales` 倒序，`limit` 1–20。
- 时间边界用 Java `LocalDate/LocalDateTime`（Asia/Shanghai）传入 SQL，不依赖 MySQL `CURDATE()`，避免时区偏差。
- 出口：发货/确认、`userName`；概览 5 字段；7/30 天数组长度正确；状态分布 5 行；TOP N 正确。

#### B9 · 联调与验收（P3）

- 前端切真实后端：`VITE_USE_MOCK=false`；如需图片代理，按 D3 加条件代理；`npm run dev` 逐页联调。
- 跑 `scripts/smoke-backend.mjs`：44 个接口逐项断言字段/类型/错误码；先执行 `reset-demo-data.sql`。
- 19 页冒烟：主流程 + 四态 + 控制台 0 error；三档分辨率不破版（复用阶段 4.5 脚本）。
- 并发验收：库存 1 抢 2 单；库存 10 抢 20 单；重复支付/取消/确认；超时旧单。
- 构建：`mvn clean package -DskipTests`、`mvn test`、`npm run build`（改前端时）。
- 文档回填：`60-测试与验收`、`91-阶段5进度看板`、`50-环境与运行`、`30-接口契约` v1.1（若校准）。
- Git：分批提交；B9 合并 `main`；打标签 `back-phase5-done`（可选）。
- 出口：第 5 节全部通过，用户验收签字/确认。

### 2.3 每个单元的执行循环

1. **写**：只改本批次声明的文件；不顺手改契约、不改前端（除非本批次明确授权）。
2. **验**：编译 → 单元/接口测试 → 关键 curl → 页面冒烟（涉及页面时）。
3. **报**：一句话说明完成内容、验证结果、下一单元；更新 `91-阶段5进度看板`。
4. **提交**：`feat(back): <单元>`；一个可验收单元一次提交；不把半成品提交到 `main`。

## 4. 技术选型确认与潜在风险

### 4.1 已定版技术栈（不再讨论）

| 层 | 选型 | 版本 | 本阶段用法 |
|---|---|---|---|
| 运行时 | JDK | 17.0.19 | 编译/运行 |
| 框架 | Spring Boot | 3.2.5 | Web/Security/Validation/Scheduling |
| 持久层 | MyBatis-Plus | 3.5.5 | 单表 `BaseMapper`，多表/统计 XML |
| 安全 | Spring Security | 6.2.x | 无状态 JWT、路径规则 |
| 令牌 | java-jwt | 4.4.0 | `JWT.create()/JWT.require()`，禁止 jjwt API |
| 数据库 | MySQL | 8.0.34 | `campus_mall`，7 表 |
| 连接池 | HikariCP | 随 Boot | 默认 |
| 校验 | spring-boot-starter-validation | 随 Boot | DTO 注解 + 手写边界 |
| 工具 | Lombok / Hutool | 1.18.30 / 5.8.27 | 实体降噪 / 通用工具 |
| 测试 | JUnit 5 + Spring Boot Test | 随 Boot | 状态机/库存/接口冒烟 |

### 4.2 本阶段需要做选择的候选方案

| 主题 | 候选 | 采用 | 理由 | 风险/应对 |
|---|---|---|---|---|
| 多表查询 | MP Wrapper 内存拼 / JPA / XML | **MP + XML** | 报告要求自定义 XML；分页/统计下推 SQL；避免全表捞出 | XML 字段与实体漂移；用 `resultType` VO + 单测校验 |
| 库存并发 | 先查后改 / 悲观锁 / 分布式锁 / 条件更新 | **条件更新** | 一行 SQL 封死超卖；无额外中间件；阶段 1 已定 | 影响行数判断遗漏；统一封装 `deductStock` |
| 超时取消 | MQ 延迟 / XXL-Job / `@Scheduled` | **`@Scheduled`** | 单机教学项目；部署简单；阶段 1 已定 | 自调用事务失效；任务调用独立 Bean 的 `@Transactional` 方法 |
| 缓存 | 不做 / 本地+Redis 抽象 / 仅 Redis | **`CacheService`，默认 local** | 无 Redis 也能跑；报告可切 Redis 演示 | 一致性问题；只缓存分类列表，写操作失效（D8） |
| 文件存储 | 本地磁盘 / OSS / MinIO | **本地磁盘** | 课程项目；零外部依赖；`/files/**` 已映射 | 路径穿越/大小/类型；UUID + 白名单 + 2MB |
| 鉴权 | Session / JWT | **JWT** | 无状态；前后端分离；阶段 2 已定 | 无法主动失效；退出仅清前端，文档写明 |
| ID/单号 | UUID / 自增 / 雪花 | **雪花 ID + 时间戳单号** | 与契约/前端字符串 ID 一致；单号可读 | JS 精度；全局 Long→String；单号唯一索引兜底 |
| VO 映射 | MapStruct / 手写 | **手写静态工厂** | 不引新依赖；字段少；可控 | 漏字段；用接口冒烟逐字段断言 |
| 测试 | 只手工 / JUnit + Node 冒烟 / 全量单测 | **JUnit 核心 + Node 44 接口冒烟** | 性价比最高；覆盖状态机/库存/字段契约 | 冒烟依赖 MySQL；脚本先重置数据 |

### 4.3 风险登记表

| ID | 风险 | 概率 | 影响 | 应对 | 触发信号 |
|---|---|---|---|---|---|
| R1 | MySQL 未启动 | 高 | 阻塞 B1–B9 | 用户管理员启动；B0 验证；建议 Automatic | `Can't connect to MySQL server` |
| R2 | 认证骨架缺口（`/auth/me` 放行、坏 token 2001） | 高 | 安全与契约不符 | B2 精确放行 + 2002 入口点 + 认证矩阵 | 无 token 访问 `/auth/me` 返回 200/500 |

| R4 | 图片 `/files/...` 404 | 高 | 联调页面破图 | D3 条件代理/契约调整；后端 classpath 兜底 | 浏览器 404 `/files/p1.svg` |

### 4.4 本阶段版本陷阱（在 `02` §8 基础上补充）

1. **`PageResult` 的 `long` 会被全局 `ToStringSerializer` 转字符串**：`serializerByType(Long.TYPE, ...)` 对原始 `long` 同样生效；分页四个字段必须显式保证 number。
2. **`@TableLogic` 不会自动作用于 XML 手写 SQL**：自定义查询/更新必须自己带 `deleted=0`。
3. **`@Transactional` 自调用失效**：`OrderTimeoutTask` 必须调用另一个 Bean 的 `@Transactional` 方法。
4. **MP 分页插件必须注册**：已注册；新增 XML 分页仍要传 `Page` 参数，否则退化为全量。
5. **`Long` 主键返回前端必须字符串**：全局已配；VO 中不要再用 `int`/`long` 承载 ID。
6. **`BigDecimal` 金额比较用 `compareTo`**：不要用 `equals`（`1.0` vs `1.00`）。
7. **上传大小有两层**：`spring.servlet.multipart.max-file-size` 与业务 2MB 校验都要有；否则异常不是 1001。
8. **MySQL 8 驱动/时区**：`com.mysql.cj.jdbc.Driver` + `serverTimezone=Asia/Shanghai`，否则统计/订单时间偏 8 小时。

### 4.5 明确不引入（本阶段反清单）

多模块 Maven、MQ、分布式锁、XXL-Job、Docker 部署业务服务、Nginx 生产配置、Swagger/springdoc、MyBatis-Plus 代码生成器、MapStruct、Druid、H2、Testcontainers、AOP 日志切面、通用 `BaseService<T>`、DDD 四层分包、Refresh Token/黑名单、OSS/MinIO。

## 6. 需确认的关键决策点

> 以下事项会改变行为或验收口径。**未确认前，对应批次不启动；其余不相关批次可先做。**
> 若回复「全部按推荐」，则按每条的推荐项执行，并在 B0 写入契约/计划变更记录。

### D1 · 销量口径：下单计还是支付计？

- 选项 A：下单即 `sales += n`，取消/超时回退（与当前 Mock 一致）。
- 选项 B：支付成功才 `sales += n`；未支付取消不回退销量（推荐）。
- 推荐：**B**。理由：销量与成交额口径一致，热销榜不出现未付款订单；答辩更好解释。
- 影响：`product.sales`、STAT-04、商品卡销量、取消/超时逻辑；A 需要额外回退且可能为负。
- 阻塞：B5a/B5b。

### D2 · 参数校验失败的 HTTP 状态

- 选项 A：HTTP 200 + `code=1001/1002`（契约 §0 与 Mock）。
- 选项 B：HTTP 400 + `code=1001/1002`（现有 `GlobalExceptionHandler` 与 `02` §5.2）。
- 推荐：**A**。理由：契约是唯一事实来源；前端只需一套 `code` 分支；与 Mock 一致。
- 影响：`GlobalExceptionHandler` 一处；前端错误分支；测试断言。
- 阻塞：B2/B9。

### D3 · 商品图片 URL 与联调代理

- 现状：后端返回 `/files/...`，前端只代理 `/api`，浏览器请求 `/files/...` 会落到 5173 → 404。
- 选项 A：保持契约 `/files/...`；Vite 在 `VITE_USE_MOCK=false` 时条件代理 `/files` → `http://localhost:8080/api/files`（推荐）。
- 选项 B：契约改为 `/api/files/...`，同步改 Mock/种子/页面；改动面大。
- 选项 C：前端所有 `<img>` 走统一 `asset()` 拼 `/api`；改动多处，Mock 模式需兼容。
- 推荐：**A**。只改 `vite.config.js` 一个文件，Mock 模式仍用 `public/files`。
- 影响：商品图、订单图、上传预览、生产部署规则；需在 `50-环境与运行` 写明 Nginx/静态服务器反代规则。
- 阻塞：B9（不影响后端接口本身）。

### D4 · 订单动作的幂等边界

- 选项 A：`pay/cancel/confirm` 幂等；`ship` 重复返回 3002（与 Mock 一致）。
- 选项 B：所有迁移都幂等；`ship` 重复且已是 `status=2` 时返回成功，不覆盖原单号（推荐，符合 `design/01` §1.4）。
- 推荐：**B**。理由：双击/并发是常态；设计文档明确「已是目标态按成功返回」；管理员误操作可由日志发现。
- 影响：状态机测试、后台发货按钮双击体验、ORD-03 断言；Mock 需同步或注明差异。
- 阻塞：B5b/B8。

### D5 · 取消收藏时「未收藏」的返回

- 选项 A：3003「尚未收藏该商品」（Mock）。
- 选项 B：幂等成功 `null`（契约字面，推荐）。
- 推荐：**B**。理由：取消是幂等动作；前端只在已收藏时调用，差异仅在异常路径。
- 影响：FAV-03；错误码测试。
- 阻塞：B6。

### D6 · 收藏列表是否包含下架商品

- 选项 B：只返回上架商品。

### D7 · 「注册用户数」是否含管理员

## 8. 执行纪律与变更控制

1. **不越界**：只改本批次声明的文件；前端改动必须单独授权；`docs/` 课程原件只读。
2. **契约优先**：字段/路径/错误码以 `design/30` 为准；发现歧义先记录，B0/B9 统一校准，不擅自改。
3. **一次一个可验收单元**：编译/测试/接口验证通过才提交；提交信息 `feat(back): ...`。
4. **每个批次更新看板**：`91-阶段5进度看板` 写“完成/卡点/下一件事”，不攒到最后。
5. **失败处理**：同一问题连续修 3 次仍不通过，停下来说明根因、已尝试方案、需要的决策，不继续打补丁。
6. **回滚**：每个批次独立提交；B9 前不合并 `main`；需要回滚用 `git revert`，不 `reset --hard` 覆盖他人改动。
7. **安全**：不提交密码/密钥；上传目录、`target/`、`.workbuddy/`、`data/` 不入库；SQL 一律 `#{}`。
8. **不做“顺手优化”**：不升级依赖、不引入新框架、不重构前端、不改表结构；除非单独批准。
