# 项目基线（每次对话开头引用）

**项目**：校园电子商务平台，前后端分离。同一平台拆成两个子系统：后台管理端与电商前台端。

**课程对应**：《前端开发技术课程设计》（第 1 学期，先做）与《后端开发技术课程设计》（第 2 学期，后做）。两门课共用一套接口契约与数据模型。

**业务闭环**：前台面向游客与注册用户，完成「浏览—搜索—详情—加购—下单—查询订单」；后台面向管理员，完成「类型—商品—订单—统计」管理。范围外：支付对接、物流轨迹、退款、优惠券、评价。

**技术栈**：前端 Vue 3.4 + Vite 5 + Element Plus 2.7 + Pinia + Vue Router 4 + Axios + ECharts；后端 Spring Boot 3.2 + MyBatis-Plus 3.5 + Spring Security 6 + JWT + JDK 17 + 单模块 Maven；数据库用本机已启动的 MySQL 8.0.34，库名 `campus_mall`。

**目录约定**：`codes/frontend`（前端工程）、`codes/backend`（后端工程）、`design/`（设计与契约文档）、`docs/`（课程原始答题纸，只读不改）。

**当前进度**：阶段 0–3 完成（基线、环境实测、领域决策、架构选型、文档规划），尚无任何业务代码。

**协作规则**：① 接口字段以 `design/03-接口契约.md` 为唯一事实来源，代码与 mock 都从它派生；② 一次只做一个可验收单元，动手前先报影响面与改动文件清单；③ 不改契约与计划外的文件；④ 每完成一个单元即提交一次 Git，保证可回滚。

**验收锚点**：功能是否算完成，以「报告 3.2 模块清单」与「契约表条目」双向可追溯为准——每条功能能指到报告章节，每个接口能指到页面上的一次点击。
